Claude Code New Update: Fable 5.2, Ultrathink & 15+ Features Explained

Everything in the November 2026 Claude Code update, explained simply: the new Fable 5.2 model and the Pro trial, automatic cloud environment setup, /storage, the /usage fix, Ultrathink, /auto-mode-setup and ten smaller changes.

Nov 10, 2026
8 minute read

Claude Code just got a new model, a way to try that model on the Pro plan this week, and a command that shows what is eating your usage limit and then fixes it for you.

Those are three of the changes. This release has more than fifteen, and a few of them will change how you work every day.

In this post I go through every one of them in plain language, with an example for each. It is the written version of my video, with all the commands and prompts in one place so you can copy them.

Fable 5.2 and the Pro Trial

Fable 5.2 is out. It generates output up to 30% faster than Fable 5.1.

The Claude Code team is honest about where it fits. Fable is a great model for big, open-ended tasks. For most everyday coding, they still recommend starting with Opus 5.5.

A simple way to decide:

  • “Fix this bug in my login screen” → stay on Opus 5.5.
  • “Plan and build the whole offline sync system for my app” → this is where Fable 5.2 fits.

To switch, run:

1

/model claude-fable-5-2

You need Claude Code v2.1.321 or later.

Try Fable on Pro this week

On Pro and Team Standard, Fable is included for up to 50% of your weekly limit through November 16. After that, Fable uses usage credits, if you have turned them on.

There may also be a Fable reset waiting for you. If you were a paid subscriber before November 9 at 10:00 AM PT, check Settings > Usage on web or desktop. The deadline to use it depends on your plan:

Plan Use the Fable reset by
Pro, Team Standard November 16, 2026
Max, Ultra, Team Premium March 8, 2027

Claude Sets Up Your Cloud Environment

A cloud session means Claude works on your code on Anthropic’s servers, not on your laptop. You can start a task from any device and it keeps going in the background.

The annoying part was the setup. Dependencies, network access and API keys were all your job.

On Pro, Max and Ultra, Claude can now set up the cloud environment for you. It tells you when the session is missing a dependency, network access or an API key, and shows you the changes to approve.

Example: you open your React Native project in a cloud session and ask Claude to run the tests. The tests need a package that is not installed, and they need your Firebase API key. Claude now flags both and shows you the setup changes, so the session does not just fail.

Two details matter here:

  • API keys go into a form, so Claude does not see the key itself.
  • The setup is saved, so your next session starts with the same environment.

Free Up Disk Space with /storage

Old sessions in the desktop app leave their worktrees on your computer. A worktree is a separate working copy of your project, and after a few weeks of daily use they add up.

Type /storage, or open Settings, to see how much space your sessions and worktrees take. From there you can clear the worktrees you have not used in a while. Your sessions, conversations and branches all stay. You can remove inactive tasks from the same place.

⚠️ Commit first. Uncommitted changes are deleted along with the worktree.

See and Fix What Is Using Your Plan

Running /usage in the terminal already showed what was using most of your plan. It now also shows how to fix it.

Press f, and Claude Code sends a prompt by itself to fix whatever it can.

Example: /usage shows that one very long conversation is burning through most of your limit. You press f and Claude takes care of it, so you do not have to work out the fix yourself.

Idle conversations are compacted automatically

There is a second saving that happens on its own. If a long conversation sits idle, Claude Code now compacts it, which means it replaces the conversation with a summary, before the cache expires. That takes about one hour.

Why it matters: resuming an uncached conversation means reprocessing your full context, and that costs usage. So if you go for lunch in the middle of a long session, Claude works from the summary when you come back.

You will see a banner when this happens, and you can turn it off in /config. It also works in VS Code and the desktop app’s Code tab for conversations over 200K tokens.

Ultrathink Is Back

Claude Code has effort levels, which control how hard Claude thinks before it answers. Put the word ultrathink in your message and Claude uses the xhigh effort level for that one turn only. Your session’s effort setting does not change.

Example:

1

ultrathink about why this migration deadlocks when two workers run it at once

Do not put it in every message. The team says you really do not need it for most tasks. It is useful when Claude is properly stuck.

Teach Auto Mode About Your Setup

Auto mode lets Claude work without asking permission at every step. By default it trusts only two things: your current working directory and that repo’s own remotes.

That is safe, but it means Claude gets blocked when it tries to push or send anything outside of that, even to other repos and services you own.

Example: your mobile app lives in one repo and your backend API in another. Claude finishes a change and tries to push to the backend repo. It gets blocked, even though both repos are yours.

The fix is one command in the terminal:

1

/auto-mode-setup

It looks at your project and at the commands Claude ran in your recent sessions there. Then it drafts a list of the repos, domains and cloud storage you trust. Once you accept the list, it is saved to ~/.claude/settings.json.

10 Smaller Updates

  1. Long conversations respond sooner. Claude Code used to send your whole conversation with every request. For most users it now sends only the new messages.
  2. Switching models is smoother. If your conversation is too long for the new model, the model you were on summarizes it before you switch.
  3. Queued messages survive a restart. If the desktop app quits, updates or crashes, the messages you queued in a local session come back when you reopen it.
  4. Cloud sessions without a repository. There is a new “No repository” option on Anthropic-hosted environments, for when you do not need a repo.
  5. Cloud sessions start even if a setup script fails. A failing script used to stop the session from starting.
  6. Effort level for cloud routines. The model picker now has an effort level when you create or edit a routine that runs in the cloud.
  7. A new safety setting. Turn on permissions.blockWritesOutsideWorkingDirectories and the Write, Edit and NotebookEdit tools refuse paths outside your working directories in every permission mode, apart from some of Claude Code’s own files. It does not limit shell commands, MCP tools or hooks.
  8. Fork subagents are on by default in the desktop app and VS Code. A fork inherits your full conversation, so you do not have to explain everything again.
  9. Background subagents use less of your limit. In Anthropic’s test on Pro and Max, sessions with background subagents used about 5% less.
  10. Claude Code no longer installs the IDE extension for you. To install or update it, use /ide from an outside terminal, or your editor’s extensions view.

The Claude Code team also published how they do code review. Claude reviews most of their changes before a person is asked to look, and the post explains how to set up the same thing.

Two Prompts from Anthropic’s Engineers

Both of these come from Anthropic’s own engineering team.

When Claude keeps stopping to ask you questions, give it the go-ahead upfront:

1

Just build and use your best judgment. Make any call that's reversible yourself, and check in later with the calls you made.

The engineer who shared it said it unblocked a large team of agents they had running.

When you want to test a design, skip the debate about whether it is flexible enough and have Claude build on it:

1

In a separate worktree, do a throwaway build of [a feature we might add later] on top of this design. Don't polish it, just tell me where the design got in the way.

Example: you have just designed your app’s data layer. Ask for a throwaway build of offline mode on top of it. You see right away where the design gets in the way, and then you delete all of it.

Takeaways

If you remember only three things:

  1. Try Fable 5.2 on Pro before November 16. Use it for big, open-ended tasks and keep Opus 5.5 for everyday coding.
  2. Run /usage and press f to cut what is eating your limit.
  3. Run /storage to get your disk space back, after you commit your changes.
